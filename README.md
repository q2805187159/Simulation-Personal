# 数字人生成工作台

数字人生成人工作台使用 React、Vite、FastAPI 和 PostgreSQL 管理人口入口、骨架仿真、版本演进、审查、发布和角色问答。

## 启动

在项目目录打开 PowerShell，运行 `docker compose up --build --wait`，然后访问 [工作台](http://127.0.0.1:5178) 或 [API 文档](http://127.0.0.1:5178/api/docs)。前端反向代理提供同源 API 和文档入口。PostgreSQL 数据保存在 Compose 卷中。使用 `docker compose stop` 停止服务。

基础 Compose 配置使用确定性 mock 模型。真实模型通过 `docker-compose.live.yml` 配置，设置 `LLM_BASE_URL`、`LLM_MODEL` 和 `LLM_HOST_SECRET_FILE`，后端从挂载的只读文件读取密钥。后端也兼容已有的 `LLM_PROVIDER=openai_compatible` 和 `LLM_API_KEY` 环境配置。当前工作机的本地 `.env` 已选用真实模型配置。容器访问宿主机上的模型服务时可使用 `http://host.docker.internal:<port>/v1`。

## 验收路径

1. 保留默认的空白出生年份与自动家庭范围，生成四川出生队列的人生骨架。系统根据种子在采样范围内确定缺省值，再按地区、生平时段和适用年龄匹配历史背景候选。在左栏展开匹配依据，点击时间线节点查看时间、参与者、依赖和证据。需要固定人物条件时，可以填写出生年份或指定家庭范围。
2. 在骨架审阅中浏览 55 族、440 项维度账本。展开事件可查看关联维度和有效时间。在填充血肉前点击「导出骨架 JSON」，可下载当前查看的修订，包含人物、事件、依赖、维度账本和校验结果。修改节点后的子版本会重算事件关联，父版本仍可单独下载。
3. 从有效分支确认骨架并填充细节。打开事件状态可查看叙事、记忆线索、情绪、倾向和表达风格，再运行全链路审查。
4. 审查通过后发布，在档案库选定同一个发布版本并创建对话。询问已知经历并继续追问，展开引用与检索过程。改用更早的日期可创建独立的时点会话。档案的「查看档案 JSON」可读取同一发布版本下的骨架、细节和报告。

命令行验收使用 `python scripts/smoke.py`，完成后打印任务、发布和会话 ID。重启后用 `python scripts/smoke.py --release <release_id>` 验证 PostgreSQL 中的发布与产物。

真实模型链路回归使用 `python -X utf8 scripts/live_smoke.py`。模型步骤耗时取决于生成批次和上游响应。表达倾向和认知状态有字段级证据及时间锚点，但未校准的人口转移率及心理量表不作为经验证统计推断。

## 代码和数据

- `backend/app/` 保存生成规则、图约束、事务工作流、模型适配和 FastAPI 路由。
- `frontend/src/` 保存生成台、生命图、审查与档案界面，默认通过同源 `/api` 访问。
- `docs/v3/` 保存研究设计来源。每个已导入人口数据帧和历史机制都有来源、时间口径和覆盖状态。缺少联合样本与转移参数的位置会保留未知或显式合成假设。
- 自动出生年份由版本化人口入口模型抽样，并记录存活条件、风险类别、删失和抽样概率。自动家庭范围在「仅本人」和「含家庭关系」间等概率采样。

- [已确认的 POC 设计](docs/superpowers/specs/2026-11-23-digital-human-poc-design.md)

在前端目录运行 `npm ci` 后，用 `npm run build` 检查类型和打包。启动 Compose 后，可用 `npm run dev` 在 `http://127.0.0.1:5173` 预览前端修改，Vite 默认经 Compose 的工作台入口访问 API。
