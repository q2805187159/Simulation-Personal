01 / executive decision

早期选型结论

截至本报告检索日，未发现一个可直接安装、持续维护、完整覆盖“所有地区与民族 + 出生或存活人口入口 + 家庭互动 + 连续生命事件 + 双时间回放”的单一开源 DSL。建议先按层组合，而不是把通用工作流、状态机或某个欧洲/美国人口模型误当成完整的中国人生成器。

当时的首选 PoC 组合 用 CUE + JSON 表达经过约束的 SkeletonSpec；OpenM++ time-based 模型作为连续风险与人口事件内核候选；CEL 只判定明确的资格和规则谓词；MiniZinc 或 OR-Tools CP-SAT 检查短时窗、日程和资源硬约束；项目自有共享事件账本保存参与者状态差分、版本 lineage、时间精度及运行凭据。

OpenM++ 内核代码有受信任的 C++ 部分；LLM 只提供数据候选，不输出、编译或执行模型源码。这个组合是高匹配度的待验证配置，不代表上述项目已替本系统完成了参数、模型或外部效度校准。 OpenM++ 平台与许可 · CUE 发行

先跑两种总体入口

从出生队列模拟到死亡，和从某日存活人口入口回溯/续推，是不同条件总体。

把共享人生事件做成一等数据

怀孕/生育、共同迁居、婚姻、照料与共享资金可以同时影响多人。

接受“分层复合”作为最佳选项

业界成熟组件分别擅长人口事件、结构校验、政策判定和局部约束，不在同一层竞争。

适配等级是依据项目需求和所查公开功能作出的定性工程判断。并非速度测试、人类真实性分数或开发工作量承诺。

02 / first principles

骨架内核的评估标准

骨架定义一组有关联的、带时间位置的结构化轨迹事件。它的用途是支持下游查询和判断，不能把所有维度先压成一条年表，也不能把人口标签单独用来确定个人结局。现有基线已定义并行 LifeSpell、个体/关系对象、Decision/Attempt、竞争事件、死亡删失、valid_time、recorded_at 和 known_at。 [设计基线的对象模型与生成顺序](虚拟人生成系统研究型设计基线_v3.0.md) · [具体历史到个体推演约定](历史暴露推演与个人路径机制规范_v1.md)

时间与人生入口

时间单位要匹配目标过程，年龄/时期/风险集不能靠下游文案补精度。起始入口分出生队列、存活截面与已故历史人口。

并行轨迹与竞争风险

居住、工作、关系、教育、健康、照料与资源持续时间可以交错。退休、死亡、迁居和工作变化需正确结束或重算待决事件。

关联个体与共享事件

共同事实以一个逻辑事件 ID 连接多参与者。家庭内支付、耗时、共同孩子及居住变化必须守恒，不应分开人再最后用文字“对齐”。

程序化描述的可信边界

LLM 可以给受限的事件候选，但不能给模型进程任意执行码。概率参数必须来自逐总体/时期校准，unknown 不等于填 0。

可复现与双时态查询

保存种子、模型与参数版本、实际随机抽值或可重放流、执行入口和结果哈希。之后发现的事实不修改早先运行和人物认知。

审核输出

接受路径、失败候选、被拒绝原因及适用约束均可回查。引擎日志不能替代经授权、去重的项目人生账本。

入口关键决定 出生队列和参照日存活样本不能只传一个 flag。若研究人员分别要已故史实和当前可交互人物，也应显式使用不同的 inclusion frame 和 target denominator。

05 / life course and synthetic-population platforms

最接近骨架任务的现成模型

OpenM++ · 通用事件微观模拟平台

MIT · 1.17.15 (2026-10-01) · case-based / time-based / event trace

按个体维护下一事件时间，更新其状态并为依赖属性重算候选；可以建 linked entities，含 time-like 与 event-like 属性机制。time-based population model 适合大量互相关联个体。其同点事件有 event time、优先级和次级顺序；必须证明 tie-order 独立于编译意外。

核心缺点 编译模型包括项目可信代码，不能把 C++ source DSL 直接暴露给 LLM。OpenM++ microdata 输出有 event trace，但跨实体变动不自动等于跨人物原子业务账本。测试必须在项目共享 event layer 上验证一次入账、退出和链接双方后果。event queue 大小也会随每个实体排队的事件数变大。

OpenM++ 首页和 MIT 许可 · v1.17.15 release · 事件 trace · 微数据输出注意项 · time-like/event-like 语义

SimPaths / JAS-mine · 生命周期领域参照模型

SimPaths EUPL-1.2 · 2026.11.08 发行 · 11 个 UK life-course modules

包含年龄、教育、健康、家庭构成、social care、收入、消费、心理健康、显示表等模块，明确家庭个人关联、变量依赖和基线初始人群。动态事件在全局 Java event list 管理，年度 recurring schedules 可按 event group sequencing。

它比通用内核提供更多可复用的生活历程模块，然而主要版本参数和 country data 面向 UK / Europe，一些在途地区版本并非都能运行；年步顺序与福利过程依赖需迁移重算。适合把模块和测试情景搬到研究库，不适合作为“中国人通用参数”直接部署。

最新发行：财富和遗赠模块说明 · country model 与 domain modules · 调度、随机 stream、实体初始化与事件机制 · 显式运行顺序说明

LIAM2 · YAML 年度微模拟

GPL-3.0 · 0.13.0 2026-07-29 · persons / households / links

作为 YAML dialect DSL 明确 persons / household entities、links、fields、period process 和执行顺序，可通过 repeats/assignment 和 period tables 实现年度人群演进。如果模型目标是“每年输出完整状态切片”，它是有力的 DSL-only 参照。

它的计算语义是某一期的 processes，哪怕 period 的数字可表不同单位，模型仍然对齐一个同步时期运行。错峰时间、日内照护、连续竞争风险、刚发生的事件精准重算，需要额外仿真与事件日志。

LIAM2 0.13.0 release · DSL model syntax 与 entity links · process semantics

DYNAMIS-POP · 受人口分布约束的个体骨架生成参考

OpenM++ time-based model + R parameter scripts · 已发布可移植模型程序

连续时间 interacting population；目标是先复现 cohort-component aggregate，再额外生成教育、schooling、ethnicity、partnership、fertility 和 health 等个人 careers。文献列出毛里塔尼亚、尼泊尔和塞内加尔 case，要求 initial population microdata 和适用时空率表；R 管估计/后处理，OpenM++ 编译模型。

选用方式 用它细读如何把人口宏观目标绑定个体转移、如何按国家调参、模块如何明确初始 population。切勿把“generic code”误读为“对所有国家无需校准”。文献有说明 DYNAMIS 分组件可取；对本项目的可分发许可责任仍须看每个 repository/data license。

发表设计与三国适配 · DYNAMIS-POP User Guide · 加载/生成初始人口

Modgen / LifePaths / Demosim · 统计机构的成熟模拟范式

Modgen 免费可用但不是 open source · LifePaths 已 discontinued · Demosim 旧方法页标注 archive

LifePaths 展示人口、家庭和职业轨迹如何共同服务长期政策模拟；2013 technical overview 明确包含 parallel careers、continuous-time competing events 和 household context，后续 microsimulation 论文记载该模型已 discontinued。Demosim 的公开方法说明则给出连续时间、等待时间和竞争事件顺序。它们是高价值的运行语义参照，但不能被列作可任意 fork 的同等开放运行时。2025 年统计局 Demosim 介绍报告提到，未来 Demosim 将改编到与 Modgen 跨兼容的 OpenM++。

LifePaths technical overview PDF · later paper noting LifePaths discontinuation · Demosim continuous time and waiting-time methods (archived) · Demosim 2025 methods report · Modgen is freeware but not open source

ML3 · 最贴近 linked lives 的论文级 DSL

ML3 0.2.8 (2022-04-25) · Apache-2.0 artifact · 原 Java 语言仓库更新缓慢

研究成果直接提出 Modeling Language for Linked Lives。群体用 agents/entities 链接彼此生命轨迹；支持时间相关 rates、任意时间 event scheduling 与依赖触发。它是这个任务的最佳“学习领域抽象”。公开稳定版版本历史止于 2022 年，加入生产栈时要面对 grammar、runtime、seed、schema migration、build 与 security 的自行维护。

ML3 形式化语言与语义论文 · Maven release metadata · ML3 version 0.2.6 archive

DEMOS · 依托 US panel 的 annual lifecycle models

BSD-3-Clause · Python · yearly agent changes

十余个人口生命周期模型覆盖教育、婚姻和交通/土地使用相关决策，模块以 US long panels 和 housing/activity datasets 估计。很适合作为 property/event inventory 和交互回归测试样例。

起始数据、美国生活地理和车辆/工作地 choice 是建设重点，不应将这些行为方程作为一般家庭生命周期事实迁移。

DEMOS source, license and model description

Longitudinal Synthetic Population Framework · 研究型 sequence sampler

MIT · 2026 v1.0.0 · EPFL research code · prior sampling + posterior population update

它把 existence、教育、工作等 life-course dimensions 建成 prior populations，并通过加权观察资料做 posterior updates，是本轮检索里直接讨论 longitudinal synthetic population 的新近开源实现。发布包含可复现的合成示例数据和 prior/posterior sampling notebooks，适合与项目的“配置率生成”“条件化在数据上生成”流程对照。

这仍是首版研究 framework，不是部署型离散事件 scheduler。其两个 synthetic example datasets 不属于真实中国代表性数据，而且示例/paper context 为交通 population trajectories。可借鉴接口概念，需先对 license notices、采样偏差和 longitudinal validation 另作审查。 仓库与 MIT license · v1.0.0 固定版本

SOCSIM / rsocsim 与 MicSim · 生命统计 gold standard 候选

R wrappers + C core · Competing risks / fertility / death / kinship

SOCSIM 模拟 population register 中所有曾经生活的个体，使用每月年龄别死亡率、fertility、marriage；能适合验证出生、死亡、婚姻和亲属网络结构及竞争等待时长。rsocsim 是近期维护的 R interface。MicSim 用多状态参数生成 continuous-time careers。两个模型都不能提供一个完整的中国社会履历事件目录、社会机会规则或问卷骨架。

rsocsim source and scope · rsocsim CRAN release · MicSim CRAN · VirtualPop

跨平台调研也发现 China-specific model papers 和 project code，但它们服务各自研究目标，如五年期人口教育劳动总体投影，或者 CHARLS 50 岁样本至 65 岁健康转移。报告不把单域研究模型包装为“全中国人 DSL”。 [中国人口低生育宏观模拟](https://doi.org/10.1073/pnas.2108900118) · [CHARISMA 50+ 健康年步模拟](https://www.nature.com/articles/s43856-025-01294-8)

08 / fork decision

何时改现有引擎源码

“尽可能改源码”不是默认优先级。先利用底层引擎暴露的 model/API 扩展点完成一次可测模型。若模型层适配能正确实现稳定 event key、linked identities、取消/重排依赖事件、参与者状态增量和 seed streams，便先验证研究样本和分支行为。

不需要 fork runtime 的情形

修正的是中国行政区划、民族分类、地方政策、灾害、source profile 或 event schema。将它们作为领域模型和版本数据，不混入内核。

增加模型 adapter 的情形

需要新关系边/事件模块输出、稳定 person_id、跨实体记录合并、事件来源、内核重复运行凭据。先围绕公开 API 和共享数据库写 adapter。

可以评估 OpenM++ patch 的情形

PoC 证明 event-time dependency 或链接实体的事件 invalidation 无法表达，且再调度正确性必须由 runtime 支持；或模型必须在一条 shared-event 中协调原子生死/多主体后果，内核无法提供钩子。

放弃 fork、换 kernel 的条件

若需复制/恢复 event queue 的全部待决状态并做时态分支，OpenM++ 提供的 run-level seed/replay 不足以恢复中段 execution；先衡量改外层 checkpoint 还是改用 Ixa/自研 event store。若 fork 反复跟不上安全/平台升级，则薄 schema adapter 更现实。

早期建议 先通过模型适配验证，再评估源码改动。分开管理“OpenM++ model C++”和“LLM 产出的 JSON skeleton”，并在实验矩阵中验证模型源码权限与规则变更机制。

09 / proof of concept

同一批骨架用例打候选平台

所有候选使用同一 SkeletonSpec、同一配置版本和适配数据。测试失败保留报告，不用 LLM 写一份看似合理叙述遮掩语义差异。

  1. 人口框条件 同时测试出生时抽样、2026 截面存活抽样和目标截止日前已死亡抽样。记录每次的 risk set 和 inclusion rule。
  2. 并行轨迹约束 固定地点、通勤时长、工作排班和陪诊任务；尝试可接受路径、花费购买服务但没有真实供给的路径和时间冲突路径。
  3. 共享事件一致性 同一次照护同时改变被照护人得到的时段、照护人劳动和家庭成本，并从双方轨迹切片读取。重复提交同 event_key 只入账一次。
  4. 事件竞争 在同一工作 spell 内竞争裁员、主动离职、退休、死亡或保持；发生首个事件后重新计算事件资格和后续风险。
  5. 发事件、记事件、获知事件 设置政策公布、生效、覆盖月、申请、批准、到账和当事人得知日期分别不同，逐一查询当时环境和 person view。
  6. 年份与时间粒度 人物只知出生年与政策资格日期处于年龄界边时，事件区间不能被悄悄变成确切周岁和准确日。
  7. 相同 seed 与分支公平性 固定同一 seed, model/data version 和 branch preconditions；优化 worker order 或加无关人物不改变已有个体决策流。
  8. 可留出的人口验证 单变量、家户联合格、生命事件顺序/间距、无事件区间、死亡/截尾按 target time series 留出；清楚报告过采样样本和 rejection/repair rate。

早期验证条件 骨架 schema 可解析、底层模型输出稳定、共同事件可复查、异常和 unknown 保留、数据支持范围可核验，以及适配人员能解释模型中的随机参数与事件优先级。现行验证条件见统一契约。

10 / project-specific finding

中国人口参数仍是单独的研究工作

本次检索发现了覆盖生育、寿命、教育、家庭、工作、健康或政策子域的成熟平台，也发现了用中国数据开发的研究模型。未发现能立即对所有中国地区、民族、世代与交叉身份运行，并持续覆盖出生至死亡、家庭共享、持续风险和完整生命周期的一体化开放微观模型。这个观察来自本次公开平台调查，并不构成“其他项目均不存在”的严格证明。

已经有中国宏观—微观人口模拟研究使用年龄、性别、教育及劳动状态做情景预测，也有基于 CHARLS 的 50 岁以上队列健康/功能年步 simulation。它们可以帮助对应 population projection 或 aging health submodel，但研究窗口、抽样人口及状态变量都没有代表全生命周期。 [中国低生育率人口预测研究](https://doi.org/10.1073/pnas.2108900118) · [CHARISMA 人群年龄与步长例子](https://www.nature.com/articles/s43856-025-01294-8)

所以平台选型解决的是“按给定过程和参数推运行”；总人口结构、事件分布、家庭 joint distribution、流动和死亡必须从具体可用资料中估计。没有资料支持的地方可以表达为“情景骨架”，不能标为全国某类人的平均真实路径。
