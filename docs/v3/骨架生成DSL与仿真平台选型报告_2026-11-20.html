面向 LLM 可修订扩展的人生事件图

人生骨架引擎选型

LLM 根据用户选项查询资料与规则，提交声明式骨架规格并调度仿真工具。仿真器按选定总体、参数与事件规则生成条理可查的人生事件图（LifeGraph）。用户可在骨架断点亲自编辑或用自然语言指示 LLM 修订，再确认版本并继续细节生成。

资料核验截至 2026-11-20平台覆盖 GitHub、PyPI、CRAN、Maven Central、crates.io、Gitee 与官方项目文档本报告无引擎性能实测，适配评价为设计审查结论
首轮概念验证配置

OpenM++ case-based 候选 + 项目图契约 + PostgreSQL 版本账本

先以独立人物和必要关联亲属组成的 case 验证连续时间与竞争事件。项目定义工具接口、骨架规格和修订事务。用户及获准的 LLM 可直接修订子分支，系统重算后继并自动检查，同时保留可回放的父版。引擎准入取决于能否从校验后的修订和锚点重新推进，并保持未受影响的父版轨迹。 全链路统一契约

OpenM++ · 首轮候选CUE 编写 · JSON 交换PostgreSQL · 事务账本LLM 工具编排 · 子分支修订
引擎承担随机过程

OpenM++ 运行可信开发者编译的模型。项目把人口入口、经验证的参数和修订约束传给适配器，收集结构化事件及参与者状态增量。

项目掌握可回放版本

项目保存事件、证据、图版本和随机输入。任意人生时点恢复、条件前史与局部重算都需用本项目用例验证。

引擎评估核对人口入口、家庭关联、竞争风险、历史规则、图修订与依赖重算。项目承担 LLM 工具编排、声明式输入校验、持久骨架断点与事务发布。

02

推荐架构与职责

从用户选项到可继续的骨架断点

用户选项与 LLM 编排

用户选定目标人群、年代、区域、约束和用途。LLM 查询授权的数据、历史与规则工具，整理输入和仍需确认的条件。

声明式骨架规格

LLM 提交受限 JSON，引用抽样框、已登记参数和规则。工具按 CUE 导出的模式及领域规则验证，再交给仿真适配器。

仿真与抽样

参数由数据估计并版本化。首轮接入 OpenM++ case-based，按固定参数推进风险、抽样事件并计算多人状态增量。

校验并保存骨架

核对事件、关系、资源和证据。共享事实通过一次事务保存，工作版本附诊断和可比较的父版本。

骨架审阅断点

用户手动编辑或用自然语言请 LLM 直接修订。系统重算和校验，用户查看差异后明确选择“继续”。

断点与版本修订。LLM 可以直接把修订写入新子分支。项目用固定父图版本计算失效的候选、事件、状态和关联人物账目。仿真适配器从已验证的检查点恢复，或固定输入并从锚点重跑相关 case。两条路径均按生效时间注入编辑约束并沿用可证无影响的父版记录。断点持久保存，用户可以退出后再回来。按下“继续”时系统核对用户看过的确切修订，校验中、存在阻断或已更新的版本先在断点处理。

锁定骨架后的流程

  1. 扩写细节。LLM 按时间段与事件生成结构化细节、人物所知、回忆及叙事。每批产物引用同一确认修订，冲突状态和未获支持的信息可以保留为未知。
  2. 独立审查与修复。规则检查硬约束，独立审查核对证据、跨批一致性和人物视角。局部内容可以定向重生成并复验，改变骨架假设或关键事件时回到断点确认新的修订。
  3. 签发到档案库。校验通过后事务保存发布清单及产物引用。读投影按发布版本构建，就绪后向用户开放该版本的问答。
  4. 第一人称问答。用户从档案库选择人物，LLM 只读检索该发布版、角色权限和提问时点内的经历、关系与记忆，再用人物的语气作答。对话记录与人生事件账本各自保存。

查看各阶段工具、产物和审查边界

个体与家户验证

焦点人物和必要亲属可组成一个独立 case。整户样本先建立统一人物与家户身份，再模拟共享事件。需要在多个 case 间同步更新同一实际关系时，重新定义模拟边界并核验权重。历史机会经人物活动地点、关系和具体验证转为个人暴露。

群体互动专项

当研究要求跨独立 case 同时作用，如邻里支持网络或共享劳动力市场，另行评估 OpenM++ time-based 模型。该模型需要独立实现和校准互动机制，仍交付相同的项目图契约。

固定运行输入固定用户选项、引擎、模式与规则版本、参数包、人口框及随机策略。
模型代码由开发者维护仿真器运行预编译模型，LLM 通过工具提交受限声明式输入和图操作。
运行可查记录工具、选项来源、图版本、父版、提交操作、随机策略和实际产物。
共享事件统一记账一次多人物事件共用 event_id，保存参与角色与各自状态增量。

ML3 · Linked Lives
语义最贴近维护较弱		Java + ANTLR；Maven Central 稳定版 0.2.8，末次发布 2022-04-25；Apache-2.0（来源包/旧版本核实）。领域语言专为 linked lives 设计；连续时间/随机竞态、年龄依赖和关联个体，模型概念与人生历程直接吻合。稳定版和维护活跃度较旧；Rust 学术重写不是已核实的持续维护替代包。接手即要负责 parser/compiler/runtime、版本兼容、随机流和测试。研究语义与语言设计参照；除非团队明确接受维护 fork，不建议新系统押注其现有 runtime。
OpenM++ case-based
与个体样本匹配		OpenM++ 一种模型模式：每个 case 可以是独立人或小型相关群体（如家庭/家系）；case 之间不互相作用。复杂 case 可保留 family network、个人事件及状态；同一总体许多独立 case 可做分层抽样，并能并行运行。case 不能自发形成跨 case 邻里/伴侣/劳动市场互动；控制多人共享事务和外部邻居统计仍由 schema/账本完成。本报告主推的出生/个人骨架模式，其 family 小网络边界须在 PoC 定清楚。
OpenM++ time-based
群体交互模式		OpenM++ 另一种模型模式：同一模拟复本中的人口实体相互作用。适合开放人口、跨人影响、疾病/迁移网络等群体路径，并可由异体实体/链接描述人群环境。每个人、每个事件都需排队，占用与运行成本随 population/状态复杂度增长；复杂性和规模有取舍。本地 RNG 也要注意更新实体键造成的变化。互动人口标定侧车。若不建跨 case 的社会网络，不要默认所有生成任务都走它。
Modgen / LifePaths

MicSim
学术研究引擎GPL ≥2		R continuous-time multi-state microsimulation 3.0 系列。适合解释/试验给定的状态空间、多状态转移率、连续时间 life course 轨迹。重点是已定义的多状态转移及研究设计，不等于带家庭关系、政策目录、共享事件账本和验证器的完整工程生成器。作为 competing risk 研究模块、hazard 模拟和结果统计基准。
SOCSIM / rsocsim

微观仿真适配器

PostgreSQL 版本账本

事件、共享参与者、状态增量、关系、修订与来源使用事务保存。审查通过的完整档案在同一事务中签发发布清单并写入待投递事件（transactional outbox）。投影、检索和通知按发布版本及消息 ID 去重。该版读投影就绪后，开放绑定同一发布清单的工具查询。

单写者原型可用 SQLite。JSONL 用于导出和离线对账。 数据库事务 · 事务发件箱模式

任务状态与重试

任务执行器保存当前阶段、清单、种子、候选失败和实际产物。交互式骨架审阅以持久任务状态暂停，确认同一图修订后继续。并发写入用父版本、请求幂等键和条件更新处理。跨长任务、多个工作进程与故障恢复有实测需求时，评估持久工作流工具。

Temporal · DBOS · Argo

子分支重算与回放

用户与获准的 LLM 都可直接创建持久化的子分支工作修订。项目从最早可能受影响的有效时间之前恢复完整状态，或按固定输入回算到锚点。适配器注入修订约束，重算候选、参与者和状态，并在新旧条件下传播影响至收敛。校验包含未受影响记录的引用与前缀摘要。校验通过的修订供用户在断点审阅。

档案回放读取已存产物。确定性复算需固定版本、数值环境、约束和随机输入。反事实对照可对语义相同的抽样地址共享随机数，实测是否降低估计方差。OpenM++ 的实体本地随机流顺序取样，同一流中增删抽取会改变后续值。计数器式随机数可用于项目自有过程。 实体本地随机流 · Random123 原论文

引擎准入与替换条件

共用用例、数据、度量和预算

准入 OpenM++
确认前史条件生成符合目标抽样分布，项目可在明确时间边界注入编辑约束，捕获所有参与者受影响状态，并验证中段恢复或确定性重跑的语义与成本。先在模型与适配器层实现。
评估 Ixa 或独立离散事件内核
用同一运行清单、图输入和验收数据验证排程、随机数、状态与候选输出。小型参考离散事件实现提供可穷举或可解析的对照，另测完整替代时的新增领域代码、参数维护和运维成本。
用 LIAM2 年度模式
问题被定义为年度 population projection，日/月事件、多人共享时段和分支前随机状态不是验收重点。年度前推不能偷换为连续人生引擎。
需要真 DSL 编辑器
模型作者确实需要书写新的语法和模块引用/跨文件检验，再加 Langium（TS）或 textX（Python）做 parser/IDE；早期让 CUE/JSON 生成人生配置更容易校验、部署和迁移。
评估引擎补丁
适配器验证定位到明确的底层阻断后，对比上游改动、长期 fork 和替代引擎。选型记录包含阻断复现、受影响范围、版本迁移费用与回退依据。
商业许可门槛
OpenM++ MIT/CUE Apache/MiniZinc MPL/OR-Tools Apache 较适合评估产品集成；EUPL/GPL/AGPL/LGPL/国内外数据集许可逐项审阅。AgentTorch 的 README 与 pyproject 对许可出现 AGPL/MIT 不一致，取得权利方澄清前不纳入商业基线。

筛选平台的概念验证

先用可验证的家庭 case，再扩大规模

首轮引擎与参考实现使用同一语义用例
验收项验证方式通过依据
存活截面前史用有解析解的小模型比较出生入口与已存活且已知属性的前史条件分布。保留入框条件、筛选率、权重和有效样本量。前史满足参照日事实，经验条件分布符合预登记误差限。已故档案和出生队列各用自己的分母。
关联输出与竞争风险一次家庭陪诊事件影响多位人物。另加先决条件变化取消待决候选，并在已知风险率的小模型检查累计发生率。单一 event_id 捕获全部参与者增量，任何一方失败则整笔未发布。事件顺序、风险与参考结果相符。
编辑约束进入引擎移动签约日期并撤销一项共享照护。以同一父版对照完整重算与依赖重算，检查新增可用和原未入选的候选。修订实际改变受影响后继，父版前缀和独立轨迹保持一致。核对所有关联人物账目和状态增量。
重启与中段恢复分别演练中断批次重启、保存并恢复待办队列和随机状态，以及从固定父版锚点重新执行。三者独立记录。检查点或锚定重跑至少一条路径可完整复算，经独立前缀和结果核对通过，重跑成本满足预算。仅有运行级补算不构成中段恢复证据。
回放、复算与分支配对从存档回放实际产物。用同一输入复算并改变线程数与调度。分支对照再以不同随机重复检验共同随机数的方差效果。同环境的规范化事件和状态一致。跨分支按语义相同的抽样地址配对，记录哪些过程解耦及其对方差的影响。
并发发布与回滚并发修订同一父版，在写入、发布及消息投递边界注入失败，重复请求及重复投递。每个请求产生唯一可回查结果。两份并发子分支仍可查询，默认读只看到经发布的完整版本，消费者按版本和消息 ID 去重。
  1. 证据与精度。只知出生年时输出年龄区间。仅有省级灾情时保留个人县级暴露、资格、供给、申请和到账的未知。
  2. 发生、获知与记录时间。2001 年离岗、2012 年回忆错年、2025 年才补录。旧问卷按原快照回放，新档案与当时人物可见事实分别核验。
  3. 节点细化。把“迁居”拆成找房、签约、搬迁、入住。保留汇总锚点和来源，检查迁居、支出与状态增量各归其主。
  4. 冲突纠偏。LLM 直接撤销冲突的合成事件，子分支保留操作和自动诊断。外部资料冲突保留原始断言与待解状态。
  5. 生命终止。死亡之后只剩关联人物或机构的后续事件，未观察到死亡的在世截面保留右删失标识。
  6. 校验对样本的影响。按目标群体保留失败、重抽、修订及发布权重，检查约束过滤是否改变入样分布。
  7. 运行成本。比较单个 case、千人批次及独立总体切片，报告吞吐、尾部延迟、峰值内存、复算代价和版本存储增量。
  8. 骨架断点恢复。保存骨架后关闭界面并恢复。用两个页面并发提交手动和 LLM 修改，检查差异及重算。仅当确认指向当前通过校验的确切修订时，系统才启动扩写。
  9. 审查返工与归档问答。分别注入局部叙事矛盾和关键时间冲突。前者按单元修复复验，后者进入新骨架修订并再次审阅。检查发布前的版本读取、投影恢复和发布后第一人称问答所绑定的快照。
通过判断。先预登记容许误差、性能预算、硬约束及例外状态，再报告各项实测结果和失败样例。通过工程 PoC 可准入该仿真模式。人口转移分布与问卷使用范围各需匹配的独立数据验收。 全链路验收契约
