外部研究 以下外部结论均基于 2026-11-24 可访问的 W3C/AAPOR/DDI 标准、学术论文与官方文档核验，明确区分标准/论文结论、官方特性与架构推断，并诚实标明适用限制。

关键外部标准、论文与架构资料

溯源、双时态与持久化工作流

  • W3C PROV-O / PROV-DM（W3C Recommendation, 2013-04-30；PROV-O / PROV-DM）：以 Entity、Activity、Agent 及 wasDerivedFrom/wasInvalidatedBy 建模血缘与失效时间。支撑：统一人口源、骨架修订、LLM 叙述与人工断言的溯源契约。限制：属通用本体，需在关系表中做扁平化投影以保证查询性能。
  • XTDB & TerminusDB（官方文档，XTDB / TerminusDB 2025）：XTDB 提供自动双时态（有效时间 + 系统时间）审计查询；TerminusDB 提供 Git 式图谱分支、差异与合并。支撑：架构方案 A/B 对比及不可变修订+显式四重时间字段设计。限制：引入新数据库会增加 POC 运维复杂度，当前 PostgreSQL 17 已满足单案级分支。
  • Transactional Outbox & Temporal（Chris Richardson Microservices.io；Temporal Web UI 文档）：事务发件箱保障主写库与读模型投影的原子最终一致；持久化执行支持从历史检查点 Reset 与克隆重跑。支撑：沿用仓库 PublishOutbox 并在批次规模化时演进至持久化工作流。

受控 LLM、问卷元数据与合成效度

  • LangGraph Checkpointing & ALCE Citation Benchmark（LangGraph Workflows；Gao et al., EMNLP 2023 ALCE）：Evaluator-Optimizer 隔离与人工中断检查点支持多日审阅恢复；ALCE 实证显示即便顶尖 LLM 在复杂问答中仍有约 49%–50% 生成内容缺乏完整引用支撑。支撑：强制独立审查员隔离、结构化输出与程序化引用 ID 校验，严禁信任模型自报引用。
  • DDI-Lifecycle 3.3 / 4.0 & AAPOR Standard Definitions (10th ed., 2023)（DDI Alliance；AAPOR 官网）：DDI 规范纵向问卷题项版次、选项编码与跳转逻辑复用；AAPOR 第 10 版规范完整访谈、拒答、中断、无资格与未知资格的最终处置编码。支撑：问卷元模型与拒答/不知道/不适用/未呈现/执行阻断的独立编码设计。
  • 合成调查样本效度实证论文（Argyle et al. 2023；Santurkar et al. ICML 2023；Bisbee et al. 2024；Park et al. 2024）：Argyle 提出条件化“硅基样本”概念验证；但 Santurkar 发现即便显式人口定向，模型对老年/丧偶等群体仍存在显著观点偏差；Bisbee 证实合成回答方差显著小于真人、回归系数偏离且同提示词跨三个月发生漂移；Park 基于深度真人访谈（而非纯人口标签）达到约 85% 真人重测一致率。适用限制：上述结论均以美国样本为主，不能外推至中文两岸四地合成骨架，必须执行独立留出集 V4 评估。

两个候选架构方案对比与选型

方案 A：纯事件溯源 + 专用双时态图数据库（如 XTDB / TerminusDB）

外部研究 以事件日志为唯一事实源，图谱修订依赖专用图数据库原生 Git 式分支或双时态引擎查询。优势：原生支持跨实体图遍历、历史任意事务时点回溯与自动分支合并。劣势：需推翻现有 PostgreSQL 17 + 16 张 ORM 表（db.py）和事务发件箱（outbox.py）；多引擎事务一致性运维成本高；对单案级（几十至数百事件）数字人图谱属于过度设计，且不利于 POC 快速交付与常规 SQL 统计聚合。

方案 B（推荐）：关系型不可变父子修订账本 + 事务发件箱 + 精确发布读模型

架构/设计建议 以现有 PostgreSQL 17 为单一事务写库，保留 GraphRevision（父子指针 + 内容哈希）与 DetailRevision 不可变快照；确定性仿真核（CUE + OpenM++/ReferenceRunner）严格前置；LLM 仅作为受控、版本绑定的有界处理器运行于独立 Worker；发布通过 PublishOutbox 事务冻结四元组并异步投影至 ExactEventProjection 读模型，问答与未来问卷仅读取不可变发布快照。优势：与现有代码零冲突演进、ACID 幂等锁成熟、随时可平滑外挂 Temporal 处理未来千人级总体批次。

四重时间语义、核心领域对象与幂等恢复契约

核心领域对象与稳定标识

代码/测试证实 现有稳定标识：job_id（生成任务）、spec_id（编译规格）、person_id（人物主体）、graph_revision_id（含 parent_revision_id 不可变骨架版本）、event_id（跨修订稳定事件 ID，拆分时原节点标 summary_node=true 并守恒分配 state_delta 与 participant_deltas）、detail_revision_id（血肉版本）、release_id 与 snapshot_id（发布冻结快照）。

架构/设计建议 需新增对象：provenance_bundle_id（W3C PROV 溯源包）、perspective_view_id（多角色可见性投影）、instrument_version_id（问卷/题项版次）、survey_run_id（单次或批次施测）、survey_response_id（独立回答记录）与 eval_report_id（留出集效度报告）。

受控 LLM 边界与隔离机制

架构/设计建议 ① 写权限隔离：LLM 绝不直接修改 GraphNode 骨架事实，自然语言修订仅生成结构化 GraphOperation[] 提案，经 validate_graph 领域约束与人工确认后落地新修订；② 结构化契约与降级：细节填充与审查强制 JSON Schema 输出（参考 OpenAI Responses API / Pydantic 校验），单事件解析失败最多重试 2 次并支持单节点降级标记而不污染整案；③ 独立审查隔离：借鉴 LangGraph Evaluator-Optimizer，审查员不共享生成器推理上下文，只接收“骨架事实 + 待审细节 + 规则清单”，并经程序化引用核验（应对 ALCE 揭示的约 50% 幻觉引用风险）。

幂等、并发与失败恢复

代码/测试证实 沿用 Idempotency-Key 请求头 + lock_command / lock_job PostgreSQL 咨询锁（artifacts.py），同 key 不同载荷返回 409 Conflict；发布阶段使用 PublishOutbox 事务发件箱，投影中断后可安全重试并复用 ExactProjectionReceipt，未完整投影前对外不可见。

架构/设计建议 POC 必需项 vs 规模化扩展：当前单案/家庭工作台保持 FastAPI + PostgreSQL 同步/轻量后台任务即可；仅当进入百人/千人级并行总体批次、跨机复算与长时间排队时，再引入 Temporal 持久化工作流与对象存储归档，避免过早引入分布式运维复杂度。

全前端信息架构、上下文契约与 13 页逐页规范

架构/设计建议 全站采用“顶部全局工作区导航（工作台 / 档案库 / [未来] 问卷研究）+ 次级阶段步进条（配置 → 骨架 → 血肉 → 审查 → 发布）+ 固定版本/时点上下文条”的三层导航。所有路由必须显式携带并校验上下文标识，防止刷新或跨标签页审阅时发生版本串台。

13 个核心页面与子页面规范

1. 生成配置空状态页
stage=generate

主要区域：左侧参数配置表单（抽样框/地域人口/参考日期/家庭范围/随机种子/细节深度），右侧“口径与边界说明板”（展示所选官方人口分母、缺失交叉表提示、合成参数声明）。关键动作：校验规格、提交生成、从历史任务克隆配置。硬约束：生成前严禁渲染虚构人物、假时间线或假进度条。

2. 生成任务与恢复页
job_id=...

主要区域：任务列表与阶段状态轨（排队/运行/待人工确认/校验失败/待修复/发布失败/就绪）、步骤耗时与错误日志折叠区（借鉴 Temporal Compact 视图）。关键动作：断线重连、幂等重试、从最近已持久化修订恢复、跳转当前阻塞阶段。

3. 骨架审阅与事件详情
stage=skeleton&graph_revision_id

主要区域：顶栏（人物摘要、引擎版本、合成声明、确认骨架按钮）；左栏（筛选器与事件列表）；主区（2D 分类泳道时间线 / 关系图谱 / 可选 3D 视图切换）；右栏（选中事件详情：有效时间、获知时间、参与者增量、状态变化、历史候选分层与未知项）。关键动作：选取、编辑、拆分、导出当前修订 JSON、确认锁定骨架。

4. 编辑、拆分与修订比较
sub=diff / split / evolve

主要区域：上方版本树/父子修订选择器；主区并排 Diff（新增/修改/删除/重算四类高亮）；抽屉含手动编辑、LLM 自然语言修订提案预览（先审后提交）、事件拆分（强制 state_delta 守恒分配）与规则升级/在世续写。关键动作：对比任意两修订、基于旧修订创建回滚子版本。

5. 维度账本与状态依据
sub=dimensions / state

主要区域：55 族 440 项维度覆盖账本（标注“概念台账非已验证量表”）；按参照日期 as_of 与参与者切换的 LifeStatePanel（区分 known/conflict/incomplete）及外部历史断言提交/冲突裁决区。关键动作：点击任意状态事实反查来源事件与原始人口/规则依据。

6. 血肉检查页
stage=flesh&detail_revision_id

主要区域：左栏绑定已确认的骨架事件目录；主区逐事件展示时间锚定人物状态、事件叙事与记忆片段；右栏展示生成元数据（model_id、prompt_version、模拟参数非心理量表说明、引用锚点列表）。关键动作：核对叙事与骨架事实偏移、触发独立审查。

7. 独立审查与局部修复
stage=review

主要区域：审查结论总览（按严重度分“结构阻断 / 叙事冲突 / 证据不足”）、问题清单与关联事件定位、局部修复前后 Diff 对比及复验（recheck=True）历史。关键动作：对叙事问题触发单事件局部修复并复验；遇结构阻断一键携诊断退回骨架审阅。

8. 发布控制页
stage=publish

主要区域：发布前不可变四元组核对单（graph_revision_id、detail_revision_id、审查通过回执、查询快照哈希）、PublishOutbox 投影状态与发布历史表。关键动作：执行发布、投影失败时安全重试、跳转已发布档案。

9. 档案库索引页
stage=archive

主要区域：按人物/发布版本/参考日期/地域筛选的档案索引表，展示最新版本、历史发布数、来源口径标签与合成标记。关键动作：进入格式化档案详情、发起时点问答、未来一键加入问卷施测队列。

10. 格式化档案详情页
archive&release_id&profile

主要区域：顶部不可变发布横幅（release_id、snapshot_id、合成来源与允许用途声明）；正文为可读传记式人生阶段摘要、关键事件卡、状态快照与维度摘要；次级入口提供“查看/下载原始 JSON”抽屉。硬约束：默认格式化阅读，不直接堆砌原始 JSON。

11. 发布版本限定问答页
archive&release_id&session_id

主要区域：顶部固定范围锁定栏（release_id、snapshot_id、role_scope="self"、as_of 截点日期选择器，范围限 birth–latest）；主区多轮对话流（标注披露级别 brief/focused/expanded 与追问锚点）；右侧可折叠“证据与检索过程抽屉”（展示命中事件、被截点屏蔽的未来事件计数、未完结 partial_record 提示与检索 traces）。

12. [未来] 问卷配置与施测页
survey/run (独立任务域)

主要区域：顶部显式标明“独立问卷施测任务（不修改人物主档案）”；配置区选择目标已发布快照（单人或未来批次）、主体/应答角色、response_at 与 reference_window、问卷版次/语言/模式与选项呈现顺序；右侧实时展示资格校验与 Draft Preview 逻辑流。

全局异常与边界状态交互矩阵

加载、空与离线恢复

  • 加载态：保留顶栏上下文与骨架屏占位，长任务显示确定阶段与已耗时（秒），不使用虚假百分比进度条。
  • 空状态：按页面精准说明缺数原因（如“未发布前无档案可问答”）并提供唯一主恢复入口。
  • 断线/恢复：顶部非遮挡横幅提示“连接中断”，保留本地草稿并提供“重新连接并校验最新修订”。

失败、冲突与范围不匹配

  • 409 冲突：并发修订或同幂等键不同载荷时，弹窗并排展示当前服务端最新修订号，禁止静默覆盖。
  • 权限/角色不匹配：请求非 self 角色或越界 as_of 时，行内提示合法边界（birth–latest）并拒绝静默降级。
  • 审查/发布失败：结构阻断直链退回骨架；Outbox 投影失败显示回执状态并提供幂等重试按钮。

缺证据、未知值与旧版恢复

  • 缺少证据/未知值：显式渲染 unknown / uncalibrated 虚线标签与说明，绝不以空字符串或 0 混淆“未观测”与“无发生”。
  • 旧版恢复：打开历史 graph_revision_id 或历史 release_id 时，顶栏固定琥珀色“历史版本只读视图”标识，编辑动作自动标注“将从该版本分叉新修订”。

完整视觉风格设计：高密度科研纸墨系统与多端降级方案

架构/设计建议 设计概念定为“可核验的科研档案台（Verifiable Archival Workbench）”：继承仓库现有 styles.css 的纸墨底色逻辑，吸收 IBM Carbon 固定字阶体系（确保高密度表格列对齐不随视口漂移）、Arena3D 的色盲安全语义色板、modern-web-guidance 的密度令牌与中文 IME 安全提交，以及 WCAG 2.2 AA/AAA（正文对比度 ≥ 7:1、非文本控件 ≥ 3:1、焦点不被遮挡 2.4.11、最小点击目标 24×24px）。任何证据层级均采用色彩 + 图标/形状 + 边框线型三重编码，绝不单靠颜色传递含义。

档案 3D 全景可视化重构规范（面向 LifeGraph3D.tsx 本地代码落地）

架构/设计建议 针对现有 frontend/src/LifeGraph3D.tsx 与 ArchiveProfilePage.tsx 视觉表现力与数据层次不足的问题，结合 Arena3D 3.0 多层网络、Three.js 自定义 GLSL 着色器及 React Three Fiber 工程实践，提出可直接交给本地 AI 代理重构的 3D 可视化规格。核心红线：真实档案节点必须居于绝对主视觉，背景与维度粒子仅作克制的上下文点云，严禁无关漂浮粒子掩盖真实节点。

1. 五层数据流形与几何映射
Data → 3D Mapping

三种 3D 空间形态平滑过渡（lerp）：① 五层星云 (strata)（默认，展示五层架构与垂直溯源光束）；② 440维星图 (Fibonacci Sphere)（球面点云星图，突出维度覆盖格局）；③ 时空螺旋 (Temporal Helix)（按 valid_time 沿垂直螺旋展开人生轨迹）。

未来问卷运行、角色访问控制与研究效度分离设计

设计文档目标 架构/设计建议 问卷模拟与日常档案问答在研究目的、数据契约和效度要求上完全不同：档案问答服务于探索性核查，而问卷模拟必须作为受版本冻结、可统计汇总、且与人物主档案物理隔离的独立研究任务。在工程实现与统计效度上必须严格二分：工程侧保证元数据完整、跳题确定、状态编码规范与全链路可复现；效度侧必须交由独立留出集验证，系统界面不得自动颁发“统计有效”背书。

端到端问卷施测流程与七元组绑定

  1. 主体与角色选择：从已发布档案库选取一个或多个 release_id，显式绑定 subject_person_id（被调查对象）与 respondent_person_id（实际应答者）。当前代码（schemas.py）仅支持 role_scope="self"（即主体与应答者为同一人）；未来扩展家庭成员代理应答（proxy_family）时，必须先经 perspective_view 过滤掉应答者在 response_at 时点不可获知的隐私事件。
  2. 问卷版次与施测情境固定：参照 DDI-Lifecycle 与 SurveyJS 元模型，锁定 instrument_id、instrument_version、item_version、选项编码及呈现顺序（支持随机化种子防顺序效应）、language、施测模式（如自填/面访/电话）以及 response_at（作答时点）与 reference_window（如“过去 12 个月”）。
  3. 确定性资格与跳题引擎：由非 LLM 确定性规则引擎计算每题资格（eligible / ineligible）与分支跳转（skip logic），仅向 LLM 呈现符合条件且可见的题干、选项与截点内证据，杜绝模型擅自回答被跳过题目。
  4. 受控作答与独立状态编码：每题回答强制输出结构化 JSON，参照 AAPOR Standard Definitions（第 10 版） 将回答状态与系统执行状态分开编码，并附带引用事件 ID 与证据强度。
  5. 独立持久化与禁止回写：问卷回答仅写入独立 survey_responses 表，严禁默认写回 GraphNode 或 LifeStateProjection；所有导出文件头强制嵌入 synthetic_source=true、模型/提示/数据版本及允许用途声明（如“仅限问卷前测与假设探索，未经 V4 验收不得替代真人抽样推断”）。

建议的问卷回答记录与状态编码核心字段

不可变绑定七元组与施测上下文

graph_revision_id · release_id · snapshot_id（按 response_at 与角色视角派生） · subject_person_id · respondent_person_id（当前仅 self） · response_at · reference_window · instrument_version_id · item_id · option_order_seed · mode · language · model_id · prompt_version · population_data_version。

分离式状态编码（严禁混为一类“空值”）

资格与呈现态：presented（已呈现）、not_presented_skip（跳题未呈现）、ineligible（无资格）。
实质与缺失回答态：valid_answer（有效编码值）、refused（拒答）、dont_know（不知道）、not_applicable（不适用）、cannot_recall（记不清）。
系统执行态：ok、timeout（超时）、guardrail_blocked（安全/边界阻断）、schema_error（结构化解析失败）。

独立于工程实现的 V4 研究效度评估框架
