## 产品目标

产品为研究、探索和受控问答生成可追溯的合成人生档案。它把人口入口和条件、历史环境、确定性人生骨架、人物状态与叙事、审查发布和版本限定问答组织成一条可恢复的工作流。系统必须让用户看清每个结果的来源、证据强度、版本范围、时间边界和验证状态，不得把合成内容包装成真人事实或已验证的总体推断。

目标设计应服务于以下使用者和任务：

- 研究者配置抽样框、地域与人口条件、参考日期、家庭范围、随机种子和细节深度，并理解配置会如何影响结果。
- 研究者检查骨架事件、并行时间线、事件关系、参与者、状态变化、维度映射、数据来源、历史环境和未知项。
- 研究者编辑、拆分、撤销或续写事件，查看版本差异和依赖影响，并保留可回读、可导出的版本。
- 研究者确认骨架后生成细节，检查人物状态与叙述的时间锚点、证据、来源和模型来源，再运行独立审查、修复和发布。
- 研究者在固定发布版本、人物视角和问答时点内检索证据、进行多轮角色问答，查看引用和检索过程。
- 未来，研究者能针对具体问卷版本和施测情境运行模拟、审阅回答状态与依据，并将问卷结果和人物主档案分开管理。

### 已实现的主链路

当前工作流由生成规格、骨架审阅、细节填充、独立审查、发布档案和档案问答等阶段组成。生成前已有配置优先的空状态与生成选项看板，人物与人生记录在提交生成任务后才出现。生成后可审阅分类时间线、事件关系、维度账本和人物状态。档案详情已有格式化阅读页面，JSON 保留为辅助查看或导出入口。核对 `frontend/src/App.tsx`、`frontend/src/WorkbenchPanels.tsx`、`frontend/src/ArchiveProfilePage.tsx` 和 `frontend/src/ArchiveReleaseView.tsx` 的当前页面编排。

后端在生成阶段将选项验证并编译为结构化规格，再由确定性领域逻辑和家庭 case 仿真建立骨架。OpenM++ 固定模型可作为运行引擎，未配置时存在用于本地对照的 Python 参考运行器。基础 Compose 使用确定性 mock 模型路径。核对 `backend/app/workflow.py`、`backend/app/domain.py`、`backend/app/skeleton.py`、`backend/app/provider.py` 和 `README.md`。不要把 LLM 文本生成与确定性骨架生成混为同一个阶段。

用户可手动编辑图，也可提交 LLM 自然语言修订建议；操作进入有父修订的子版本，并经过结构和领域约束校验。系统支持选取修订、版本差异、事件拆分、骨架升级或续写，以及对当前选定修订导出 JSON。填充细节前要确认具体骨架修订。核对 `frontend/src/App.tsx`、`frontend/src/SkeletonDimensions.tsx`、`frontend/src/SkeletonEvolution.tsx`、`frontend/src/SplitEventPanel.tsx`、`backend/app/schemas.py`、`backend/app/main.py` 和 `backend/app/workflow.py`。

细节生成包括按时间锚定的人物状态、事件叙事和记忆内容；细节有模型及提示版本等来源信息。审查发现的问题可局部修复并复验，结构问题会返回骨架审阅阶段。发布把图修订、细节修订、审查和查询快照固定到同一发布版本。问答会固定发布版本和 `as_of` 时点，按可见证据检索，支持多轮追问、逐步展开、引用及检索过程显示；问答是只读的，不应改写人生主档案。核对 `backend/app/persona.py`、`backend/app/dialogue.py`、`backend/app/chat.py`、`backend/app/workflow.py` 和 `backend/app/main.py`。

## 设计约束与体验原则

- 入口必须是实际可工作的研究工作台。生成前只展示配置与空状态，不虚构已生成的人物、人生节点或进度；提交任务后进入骨架审阅。已实现的这一行为需纳入目标架构与视觉方案。
- 将主流程设计为可见、可恢复的阶段状态。对排队、运行、需要用户确认、校验失败、待修复、发布失败和成功等状态分别设计页面反馈与恢复操作。
- 保留专业研究工具的高信息密度和扫描效率。人物摘要、筛选、事件时间线、图关系、维度账本、来源详情、状态依据和版本比较应在合理的信息层级中协同。
- 格式化人物档案是常用阅读方式；保留原始结构数据的查看和下载能力作为辅助入口。对来源、引用和合成状态提供可追溯的逐层详情。
- 让用户明确看到个人事实、研究来源、历史背景候选、模型生成叙述、未知项和未校准量表之间的界线。可视化不得暗示不存在的证据强度或统计效度。
- 常见操作包括查看证据、选取事件、编辑、拆分、比较修订、回退、导出、确认骨架、查看审查问题、发布和沿证据追问。为这些操作提出稳定且符合网页无障碍约定的交互方式。
- 覆盖宽屏桌面、窄屏笔记本和平板/手机降级方案。说明核心表格、图、时间线、侧栏和详情在小视口下如何切换或折叠，不以隐藏必要证据作为响应式方案。
- 提出完整前端的一致视觉系统，包括色彩与语义状态、中文字体和数字字体、字号层级、间距、边框/表面、密度、控件、焦点与键盘态、数据图例、证据引用、图表及空/错/加载状态。风格应契合严谨、可复核的研究工具，避免营销型首页和装饰性空洞内容。
- 对未来问卷页使用相同的整体系统，但显式标明其与现有档案问答是不同任务。问卷施测输入、角色/时间信息、回答状态和统计视图都要有独立而关联清晰的呈现。
